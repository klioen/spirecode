# Intent

精简 Task 列表页与详情页的视觉层级和信息密度，让核心状态、当前执行、最新结果与主要操作更容易扫描，同时保留现有数据、操作、状态限制和 Renderer/Main 边界。

风险判定：标准变更。它调整多个 Renderer 组件的用户可见结构、响应式样式与测试，但不改变 Task 状态机、持久化、IPC、Main 服务或权限边界。

# Spec

- 列表页概览固定为总数、进行中、待处理、已完成四项；后三项继续切换现有列表视图，总数只读。近七天指标、耗时、Token 与完整状态分布不再常驻展示，底层 Dashboard DTO 保持不变。
- 视图切换、搜索和项目筛选组成一条紧凑、可换行的工具栏；通知、新建、更多菜单、分页、空态、加载与重试保持可用。
- 每条任务只常驻展示标题、项目、可读状态和更新时间，不展示 workspace、耗时或 Token；长文本截断但保留 title，交互行保留明确的 focus-visible 状态。
- 详情页顶部集中返回、标题、状态和当前可用主要操作，并在足够宽度下保持 sticky。
- 当前执行和最新结果保留强调容器；项目、workspace、耗时、Token 合并为无独立卡片的紧凑元数据行。
- 需求、验证详情和历史 Run 使用分隔式折叠区域。需求仅在 backlog 默认展开；需要立即处理的验证状态可以默认展开，其余验证详情与历史默认收起。
- 最新报告、测试汇总、交付链接、错误、注意状态及全部现有操作和状态限制保持清晰可用。
- 继续使用现有主题 token、容器查询、语义化状态文本、可访问名称和 focus-visible 样式；不新增依赖或文案能力。

# Plan

1. 先更新 TaskPage、TaskDetail 与布局测试，覆盖四项概览、精简列表字段、紧凑元数据、折叠验证/需求/历史和窄容器结构，并确认旧实现失败。
2. 精简 `TaskDashboard` 和任务行展示，移除仅为已隐藏指标服务的 Renderer 计时与格式化逻辑，同时保持筛选、错误和刷新行为。
3. 重组 `TaskDetail` 的验证详情与资源元数据，保留所有操作回调和状态门控。
4. 调整 Task 专用 CSS 为紧凑工具栏、列表行、扁平详情分区和宽/窄容器响应式布局。
5. 运行 focused Renderer tests、lint、typecheck、Renderer/build 验证及 `pnpm check`；记录无法完成的原生视觉检查。
